# 科学图鉴 Science Atlas — 版本历史

版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)：`主版本.次版本.修订号`。

## 版本管理约定

- **单一来源**：版本号只写在 `science-atlas/app/build.gradle.kts` 顶部的
  `appVersion` 与 `appVersionCode`，`VERSION` 文件、dist 产物名与 Release 标签都由它派生
- **versionCode 必须递增**：否则 Android 不会把新包识别为升级，已安装旧版的用户收不到更新
- **每次发布固定三步**：改版本号 → 构建 → 打 tag 并发 Release，资产随 tag 一起冻结
- **不覆盖已发布的资产**：Release 一旦发布就不再改动其 APK，内容变更一律走新版本号
- 版本号含义：主版本号变动表示数据格式或架构不兼容；次版本号表示新增功能或内容；
  修订号表示缺陷修复

### 与历史图鉴的版本号相互独立

本仓库同时维护两个可发版的 Android 项目，各有独立的版本号、VERSION 文件、
CHANGELOG 与 git tag：

| 项目 | 版本文件 | CHANGELOG | tag 前缀 |
|---|---|---|---|
| 历史图鉴 `history-atlas` | `VERSION` | `CHANGELOG.md` | `v1.1.5`（无前缀，历史沿用） |
| 科学图鉴 `science-atlas` | `science-atlas/VERSION` | `science-atlas/CHANGELOG.md` | `science-atlas-v1.0.0` |

tag 带项目前缀是为了让两个项目的版本号互不抢同一个 tag。
发版用同一套工具，靠 `--project` 切换：

```powershell
python tools\release.py 1.0.0 --project science-atlas
python tools\check_version.py --project science-atlas
```

## v1.0.2 — 2026-11-12

修复地理学科时间轴刻度全部显示为「前19亿年」的问题。天文 / 物理 / 化学不受影响。

### 问题

打开地理时间轴，整条轴的年份刻度清一色是「前20亿 / 前19亿」，
近现代的大发现（板块构造、卫星遥感、GIS）全部挤在最右侧一个像素点上，
实际等于不可用。其余三个学科正常。

### 根因

`TimelineAxis` 的默认视窗计算里叠了两个缺陷：

1. **缩放下限过紧**：`MIN_PPY = 0.0008`（每年 0.0008 像素）。
   地理 55 条事件跨度约 39 亿年，1080px 画布下自然像素率是 2.77e-7，
   被下限强行抬到 8e-4 之后，可见区间只剩 ±67 万年——
   中心恰好落在地质深时中段，于是刻度全是「前 X 亿年」。
2. **视窗定位对离群点没有抵抗力**：旧逻辑取「年份 2%~92% 分位」。
   地理数据里「地球形成（-46 亿年）」「大氧化事件（-24.5 亿年）」等
   11 条地质深时事件把分位中心拖到前 19 亿年；
   而其余 44 条事件集中在公元前 5 亿年之内，全部挤成一个点。

### 修复

- 缩放下限放宽到 `1e-9`（1080px 可容纳约 1 万亿年跨度）
- 视窗定位改用 **IQR（四分位距）离群点过滤**：
  只取 `[Q1-1.5·IQR, Q3+1.5·IQR]` 内的年份定位视窗，
  地质深时事件不再拖偏视窗；过滤后样本不足 4 条时退回全量
- 视窗计算抽成 `AxisViewportCalculator` 纯函数，
  脱离 Compose 可单元测试；TimelineAxis 调用它，
  缩放常量单一来源，避免「算出来的」和「夹回去的」上下限不一致
- 刻度档位补齐 20 亿 / 50 亿 / 100 亿年，细网格推导同步

### 回归防护

新增 `AxisViewportCalculatorTest` 17 个用例，其中核心三条
直接用仓库里的真实 geo.json 断言：

- 视窗中心不得落在地质深时（修复前是 -19.5 亿年）
- 多数事件必须落在默认视窗内（修复前可见仅个位数）
- 视窗半跨度 ≥ 1000 年，保证近现代事件可分辨

### 验证

- 全项目 64 个单元测试全绿（47 旧 + 17 新）
- 真机（华为 ALN-AL10）实测：
  地理刻度「前7000万 → 公元元年 → 1000」连续递进；
  天文 1200–2100 / 物理 1650–2050 / 化学 1675–2075 无回归

### 附带修复

`pre-commit` 钩子因 CRLF 行尾整体失效——Git Bash 执行 CRLF 脚本时
`\r` 混入参数，`$PROJECT_DIR` 变成 `history-atlas\r`，
导致 `sed` 读不到 `build.gradle.kts`、版本检查形同虚设。
`.gitattributes` 新增 `.githooks/* text eol=lf` 防止复发。

## v1.0.1 — 2026-11-12

修复 `gradlew` 缺失可执行位导致 Linux / CI 无法运行构建脚本的问题。应用内容与 v1.0.0 一致。

### 问题

`science-atlas/gradlew` 在 git 中的文件模式是 `100644`（无可执行位），因此在
Linux、macOS 或 CI（Ubuntu）上执行 `./gradlew` 会直接报
`Permission denied` 并以退出码 126 失败。Windows 上用 `gradlew.bat` 不受影响，
所以本地一直没暴露。

`feat(science-atlas)` 给 CI 加上 `testReleaseUnitTest` 与 release 构建步骤之后，
该问题在 CI 上表现为「构建验证 / 单元测试」作业 exit code 126。

### 修复

把 `science-atlas/gradlew` 的 git 文件模式改为 `100755`，与 `history-atlas/gradlew`
保持一致。

### 验证

- 本地 `./gradlew.bat :app:testReleaseUnitTest`：通过
- CI 由 Ubuntu 执行 `./gradlew :app:testReleaseUnitTest`：通过

## v1.0.0 — 2026-11-11

首个版本。地理、天文、物理、化学四门学科的离线科普 App。

### 内容

四个学科共 70 个分期、226 条发现事件、151 位科学家，全部打包在 APK 内，
无网络权限、完全离线可用。

| 学科 | scope | 分期 | 事件 | 科学家 |
|---|---|---|---|---|
| 地理 | `geo` | 18 | 55 | 37 |
| 天文学 | `astro` | 18 | 45 | 29 |
| 物理学 | `physics` | 17 | 59 | 45 |
| 化学 | `chem` | 17 | 67 | 40 |

学科内容覆盖：

- **地理**：地质年代（冥古宙至今）、地理大发现时代、板块构造时代、
  气候科学时期、地貌过程分期、环境科学与可持续地理、地图学与地理信息
- **天文**：宇宙学模型、空间观测时代、观测手段演进、恒星与天体物理学、
  行星科学与太阳系探测、系外行星与生命搜索、宇宙学观测与大爆炸证据链
- **物理**：古典力学、热学与统计物理、电磁学、相对论、量子力学、
  核物理与粒子物理、固体与凝聚态、宇宙学与统一理论
- **化学**：炼金术与早期化学、原子论与道尔顿、周期表时代、有机化学时代、
  电化学与工业化学、结构化学与生物化学、现代化学与新材料

数据契约见 [`data-science/SCHEMA.md`](../data-science/SCHEMA.md)，
数据由 `tools/sci_content/gen_*.py` 生成，可复现可修改。

### 功能

| 页面 | 说明 |
|---|---|
| 首页 | 四学科切换 + 内容统计 + 功能入口 |
| 分期总览 | 分块年表树（阶段脊柱 + 三级色块），可下钻 |
| 时间轴 | 横向缩放时间轴，捏合缩放 / 拖动平移，事件按重要度分层 |
| 科学家志 | 按身份 + 分期筛选，分组浏览 |
| 发现流 | 按时间与分类浏览全部事件 |
| 搜索 | 跨分期 / 事件 / 科学家实时过滤，命中关键词高亮 |
| 四科对照 | 任选两门学科并排，共享「聚焦年代」滑块同步高亮与滚动 |
| 三个详情页 | 分期 / 事件 / 科学家，含生平、成就、名言与关联跳转 |

### 已知取舍

- **地质深时用相对尺度**：「地质年代」等分期的起始年写作 `-4600000000`（约 46 亿年前），
  超出 32 位整数范围，因此模型的年份字段用 `Long` 而非 `Int`。
  时间轴与脊柱刻度会把这类数值折算成「亿年 / 万年」显示。
- **专题补充单独成组**：跨尺度、跨学科的专题分期无法与编年主干并排，
  单独列在年表树下方，避免互相重叠把主线挤没。
