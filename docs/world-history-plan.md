### 1.3 三个结构性问题

**问题 A：地区失衡——非西方占比过低**

以人物为例，粗略估计欧美相关人物占 60% 以上，而亚洲（除中国）、非洲、拉美、
中东合计不足 20%。这不符合「世界史」的定位。

**问题 B：跨文明交流时期 100 事件 / 0 人物**

这是最刺眼的结构异常。100 个事件（占世界史 23%）挂在一个零人物的容器下，
意味着这些跨文明事件无法通过「人物」维度被检索到，浏览体验断裂。

**问题 C：多个时期「有人无物」或「有物无人」**

- 有人无物：`w-cold-war` 9 事件 / **0 人物**（冷战这么重要的时期竟然没有人物条目）
- 有物无人：`w-age-of-sail` 2 事件 / 0 人物；`w-africa-east` 5 事件 / 0 人物
- 近乎空白：`w-medieval-south-asia`（2 事件 / 1 人物）、`w-mughal`（4 / 0）

## 五、执行注意事项

基于前几轮的踩坑经验，实际执行时需遵守：

### 5.1 区间约束（最容易出错）

事件与人物的 `year`~`yearEnd` **必须完整落在声明 `periodId` 的区间内**，
否则会被 `fix_span_events.py` 上移到父时期，导致「补了但落在别处」。

**执行前必做**：生成脚本中加区间预检（`_gen_zzbq*.py` 里已有模板）。

### 5.2 分片命名

- 世界史事件 → `data/.tmp/world_events_*.json`（**纯数组**，不是 `{"events":[]}`）
- 世界史人物 → `data/.tmp/world_fig_*.json`（**纯数组**）
- ❌ `evdata_*` / `figdata_*` 会被归入**中国史** scope

### 5.2b ★ 人物会被按生卒年自动重排 periodId（最易被忽略的约束）

`tools/reassign_figures.py` 会按 `birthYear`/`deathYear` 重新归位人物，规则是：

1. 若人物当前 `periodId` 的区间**能容纳生卒年**，则不动；
2. 否则在其所属**顶层分组**（`GROUP["world"]` 列表）内，找最窄的能容纳时期；
3. 同组内找不到，才放宽到全部时期（但排除跨度 > 1200 年的笼统时期）。

**两个致命影响**：

- **规划中「甘地挂 w-mughal」这类安排会被自动改掉**——甘地（1869-1948）与
  `w-mughal`(1526-1857) 区间不重叠，会被挪到别的时期。必须为近现代非西方人物
  建**区间正确的时期**，否则挂哪都不对。
- **新建的时期必须先加入 `GROUP["world"]` 列表**，否则该组的候选池里没有它，
  人物永远不会被归入。这是纯代码改动（`tools/reassign_figures.py` 的 `GROUP` 常量），
  容易漏。

**执行要求**：
- 建新时期的同一次提交里，同步更新 `reassign_figures.py` 的 `GROUP["world"]`
- 每个人物的 `birthYear`/`deathYear` 必须落在其 `periodId` 区间内（或跨度容差内），
  生成脚本应加预检

### 5.2c 事件与人物归期机制不同

| 对象 | 脚本 | 规则 |
|---|---|---|
| 事件 | `reassign_periods.py` + `fix_span_events.py` | 按 `year`~`yearEnd` 落区间，跨度超界则**上移到父时期** |
| 人物 | `reassign_figures.py` | 按生卒年落区间，在**同组内**选最窄时期 |

两者判据不同，不可混用经验。

### 5.3 id 命名

- 新事件：`ev-zzbq13-*`（延续序号）
- 新人物：`fig-zzbq13-*`
- **必须避开已存在的 id**，尤其是跨 scope 冲突（v1.9.0 刚清理完 13 个）

### 5.4 引用校验

生成前必须校验所有 `figures` / `relatedEvents` / `relatedFigures` 引用存在，
否则流水线会补出英文空壳（如 `jin taikang`）。

### 5.5 重复检查

新增前先按「名称 + 年份」查重——本规划已标注哪些人物「已在库」，
实际执行时仍需用脚本复核（`find()` 按 name + alias 双查）。
